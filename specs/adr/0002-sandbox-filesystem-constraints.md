# ADR 0002: Claude Code Bashツールのサンドボックスファイルシステム制約への対応

## ステータス

確定済み（実装済み）

## 背景

GitHub Actions上でClaude Codeを実行する際（`.github/workflows/claude.yml`等）、Bashツールはデフォルトでサンドボックス化される。サンドボックスの書き込み許可対象は**作業ディレクトリ（チェックアウト先）とセッション専用の`$TMPDIR`**に限定され、**裸の`/tmp`直下は対象外**である。

この制約に気付かずに、一時ファイルを`/tmp`直下に置くコードを書くと、PostToolUse/Stopフック等の複数のステップ間でマーカーファイルを共有する際に問題が発生する：
- PostToolUseフック側で`/tmp/marker`への書き込みがサンドボックスにブロックされる
- または、ブロックされずに書き込まれても、Stopフック側で読み取り時に別のサンドボックスプロセス内で実行されるため、ファイルが見えない
- 結果として、マーカーを永遠に検出できず、無限ブロック状態になる

**詳細**: https://code.claude.com/docs/en/sandboxing の「Temporary directories」節参照。

## 決定

CI上の一時ファイル・マーカーファイルは、すべて**作業ディレクトリ配下**に置く。`/tmp`直下は使わない。

- CI応答確認hookのマーカー: `.ci-tmp/` 配下
- タップ座標取得の中間ファイル（uiautomator dump）: `work/` 配下（既存のスクリーンショット保存と同じ）
- その他の一時データ: 作業ディレクトリ配下

作業ディレクトリ配下に置いたファイルは`.gitignore`で除外する（例: `.ci-tmp/`、`/work/`）。

## 根拠

- Bashツールのサンドボックスは、OS（macOS Seatbelt、Linux seccomp等）のプリミティブで実装されており、Bashプロセス・その子プロセスの全ファイルシステムアクセスを制御する
- 同じセッション内であってもプロセスが異なると、サンドボックス内で書き込まれたファイルが他のプロセスから見えない場合がある
- PostToolUse/Stopフック、複数のBashステップ（ワークフロー内）など、複数のプロセスで一時ファイルを共有する場合、作業ディレクトリ配下が確実

## 影響

- **変更対象**: 
  - `.claude/hooks/mark-ci-reply-posted.sh` — マーカー保存先を`/tmp` → `.ci-tmp/`に変更
  - `.claude/hooks/require-ci-reply.sh` — マーカー読み取り先を同じく変更
  - `.claude/skills/flutter-android-operate/SKILL.md` — UIテスト座標取得のuiautomator dump保存先を`/tmp/wd.xml` → `work/wd.xml`に変更
  - `.gitignore` — `.ci-tmp/`を追加

- **今後のガイドライン**:
  - 新しいスキル・エージェント・hookを書く際も、CI上の一時ファイルは作業ディレクトリ配下に置く
  - ローカルスキルで`nohup ... > /tmp/...`を使う場合、CI版スキルを別に作る際は作業ディレクトリに変更する

## トレードオフ

- 一時ファイルが作業ディレクトリ配下に溜まる可能性がある → `.gitignore`で除外し、不要になったら手動削除
- ローカル・CI間でスキル実装が分かれるケースが増える可能性 → 同じ手順を共有する際はコメント・ドキュメントで明示
