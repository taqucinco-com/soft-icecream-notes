# icecream-log 要件定義書

## 概要

食べたソフトクリームの写真をFlutterモバイルアプリ（iOS / Android）に取り込むと、写真のExif情報から撮影日時と位置情報を読み取り、「いつ・どこで食べたか」を自動的にメモとしてリスト化する。位置情報からお店を推定して紐付け、記録はリスト表示とマップ表示を切り替えて閲覧できる。また、ソフトクリームを作ったサービングマシン（カルピジャーニ、日世など）ごとにメモを絞り込める。

## ユーザーストーリー

- ユーザーとして、食べたソフトクリームの写真を取り込むと、いつ食べたかが自動的に記録されてほしい。手入力の手間を省きたいから。
- ユーザーとして、写真の位置情報からどのお店で食べたかの候補を教えてほしい。店名まで正確に記録したいから。
- ユーザーとして、記録をリストだけでなく地図上でも見たい。行った場所を視覚的に振り返りたいから。
- ユーザーとして、どのサービングマシンで作られたソフトクリームかで絞り込みたい。好きな機械のソフトクリームを再訪したいから。
- ユーザーとして、食べた味の感想を複数の箇条書きで記録したい。2回目以降の来店では前回と異なる感想を持つかもしれないから。
- ユーザーとして、味の特徴（口当たり・素材の活かし方・個性的・フレーバーの良さ・温度管理）を五角形のグラフで視覚的に把握したい。
- ユーザーとして、メモ一覧・メモ作成・設定をボトムナビゲーションからすぐに行き来したい。
- ユーザーとして、将来のメモ公開に備えてニックネームとアイコンをプロフィールとして設定しておきたい。
- ユーザーとして、設定画面で今使っているアプリのバージョンを確認したい。

## 受け入れ条件

### REQ-1: 写真取り込みと日付記録

- WHEN ユーザーが写真を選択または撮影してメモを作成する THEN システムは 写真のExif情報から撮影日時を読み取り「yyyy-MM-dd」形式でメモに記録する SHALL。
- IF 写真にExifの撮影日時情報が存在しない THEN システムは 日付欄を空欄のままメモを保存する SHALL。
- WHEN ユーザーが日付欄が空欄のメモを開く THEN システムは 日付を手動で入力・編集できる SHALL。

### REQ-2: 位置情報の抽出と店舗紐付け

- WHEN 写真にExifのGPS位置情報が含まれる THEN システムは その位置情報をもとに近隣の店舗候補を検索してユーザーに提示する SHALL。
- WHEN ユーザーが提示された店舗候補を確認する THEN システムは ユーザーが候補から選択、または店舗名を手動で修正できる SHALL。
- IF 写真にExifのGPS位置情報が存在しない THEN システムは 位置情報および店舗名欄を空欄のままメモを保存する SHALL。
- WHEN ユーザーが位置情報・店舗名が空欄のメモを開く THEN システムは 位置情報・店舗名を手動で入力・編集できる SHALL。

### REQ-3: リスト表示

- WHEN ユーザーがメモ一覧画面を開く THEN システムは 各メモを日付・お店・サービングマシンを含む形で一覧表示する SHALL。

### REQ-4: マップ表示

- WHEN ユーザーが表示切り替え操作を行う THEN システムは リスト表示とマップ表示を切り替える SHALL。
- WHEN マップ表示中である THEN システムは 位置情報を持つメモを地図上にピンとして表示する SHALL。
- IF メモに位置情報が無い THEN システムは そのメモをマップ表示に含めない SHALL。

### REQ-5: サービングマシンの記録とフィルタリング

- WHEN ユーザーがメモを作成・編集する THEN システムは サービングマシンを事前定義リスト（例: カルピジャーニ、日世）から選択、または自由入力で記録できる SHALL。
- WHEN ユーザーがサービングマシンでフィルタ条件を指定する THEN システムは 指定されたマシンに一致するメモのみをリスト表示・マップ表示に反映する SHALL。

### REQ-6: 感想の記録

- WHEN ユーザーがメモを作成・編集する THEN システムは 感想を複数件、箇条書き形式で追加・編集・削除できる SHALL。
- IF メモに感想が1件も登録されていない THEN システムは 感想欄を空のリストとして表示する SHALL。

### REQ-7: 味の5軸評価とレーダーチャート表示

- WHEN ユーザーがメモを作成・編集する THEN システムは 口当たり・素材の活かし方・個性的・フレーバーの良さ・温度管理の5項目をそれぞれ1〜5の5段階で評価できる SHALL。
- WHEN ユーザーがメモ詳細画面を開く THEN システムは 登録済みの5軸評価を五角形のレーダーチャートとして表示する SHALL。
- IF 5軸評価が1件も入力されていない THEN システムは レーダーチャートの代わりに未評価である旨を表示する SHALL。

### REQ-8: ナビゲーション構造

- WHEN アプリを起動する THEN システムは 画面下部に「メモ一覧」「メモ作成」「設定」の3項目からなるボトムナビゲーションを表示する SHALL。
- WHEN ユーザーが「メモ一覧」または「設定」を選択する THEN システムは 対応するタブ画面に切り替え、各タブの操作履歴（画面スタック）をタブ切り替え後も保持する SHALL。
- WHEN ユーザーが「メモ作成」を選択する THEN システムは メモ作成画面をフルスクリーンモーダルとして表示する SHALL。
- WHEN ユーザーがメモ作成画面（モーダル）を閉じる THEN システムは 直前に選択していたタブ画面に戻る SHALL。
- WHEN ユーザーが「メモ一覧」タブを開く THEN システムは リスト表示とマップ表示を切り替えられる SHALL（REQ-3, REQ-4を参照）。

### REQ-9: プロフィール設定

- WHEN ユーザーが設定画面でニックネームを入力する THEN システムは 入力されたニックネームを保存する SHALL。
- WHEN ユーザーが設定画面でアイコン画像を選択する THEN システムは 選択された画像をアイコンとして保存し、設定画面に表示する SHALL。
- WHEN ユーザーが設定画面を開く THEN システムは 現在のアプリバージョンを表示する SHALL。

## スコープ外

- 店舗検索に利用する具体的なAPI/データソースの選定（設計フェーズで検討）
- 地図表示に利用する具体的なSDK/プロバイダの選定（設計フェーズで検討）
- SNS等への共有機能
- オフライン動作時の詳細な同期仕様
- 同一店舗・同一フレーバーにまたがる複数メモの感想/評価の横断比較表示（レーダーチャートの重ね合わせ、店舗単位の感想一覧画面など）
- メモの公開機能そのもの（REQ-9のニックネーム・アイコン設定は、将来の公開機能に備えたアカウント設定の器のみを今回の対象とする）
